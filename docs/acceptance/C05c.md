## Key negative tests and expected results

| Context | Target | Expected |
|---|---|---|
| Anonymous | `/admin`, `/admin/mfa` | Redirect to `/admin/sign-in` with no sensitive content |
| Anonymous | `/api/admin/security-check` | 401, `{ "authorized": false }`, no-store |
| Normal customer, including metadata role `admin` | Admin API | 403, no membership grant |
| Approved admin AAL1 | Admin page | Redirect to MFA |
| Approved admin AAL2 + verified TOTP | Admin page / security-check | Landing area / 200 `authorized: true` |
| AAL2 JWT after factor removed (disposable DB) | `iojh_admin_aal2()` | False |
| Revoked membership (disposable DB) | `iojh_admin_aal2()` | False immediately |
| Two active members (disposable DB) | Unique index | Second grant fails |
| Anonymous/customer SQL role | `private.admin_memberships` direct write | SQL permission failure |
| Privileged grant without transaction reason (disposable DB) | Audit trigger | Error, no grant |
| Owner attempts membership `DELETE` (disposable DB) | Audit trigger | Error, use revoke |

## Deployment and rollback

- Source ZIP is a narrow overlay. No deleted files, new package dependencies, server endpoints or secret/config changes.
- Additive migration preserves the existing RPC interface, owner membership, one-active uniqueness, historical audit events and C05b server routes.
- If the migration fails, its enclosing transaction rolls back. **Do not alter an existing production system or reset a linked DB.** Diagnose on local/disposable DB first.
- Do not roll back database security controls casually to regain access. Preserve records, follow the owner recovery runbook, fix forward after review. Future software version rollback remains compatible with current function signatures, but will not restore weaker database behavior.
